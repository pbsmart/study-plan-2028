# 2028 高考弹性学习计划 · 循序

面向在职备考者的中文学习计划网站，使用 Vue 3、TypeScript 和 Vite。黑白配色，支持浅色、深色与系统主题，适配手机和电脑。

## 页面与计划

- 学习概览：当前手动学习序号、实际学习时长与打卡进度。
- 学习路线：第 1—84 周；按知识点和阶段浏览，不绑定日期。
- 六科学习路径：语文、数学、英语、物理、化学与待确认第三科。
- 首四周学习：完整原创基础课程入口，旧版首四周打卡独立保留。
- 学习周：周次、科目与实际学习记录；点击“开始专注学习”后只展示当前课程的一节。
- 专注学习：单列阅读、按需展开目录与来源、上一节/下一节、答案点击揭示。退出后回到本周计划，浏览与阅读均不会推进保存的周次。
- AI 问答：专注页点击「问 AI」按需打开；使用自己的 DeepSeek Key，手动选择当前知识点或一道题并预览后提问。
- 设置与备份：第三科、默认可选配额、主题、历史日志及 JSON 导入导出。

第三科默认显示“待确认”，生物只是可更改参考，可切换地理或思想政治。切换后显示各自课程，历史时长保留原科目名称。

学习周是教学序号，完全不与日历周、月份或考试倒计时绑定。进度由用户手动前进，可以停留、重复复测或回看；浏览后续周不会改变当前进度，任何按钮都不会自动假装完成任务。

本批课程为 **第 1—84 周共 672 个学科课次（2688 道基础例题、练习与复测题，另有 96 道诊断题）的完整原创基础讲解，以及第 1—84 周的全部周纲**；全部 84 个编号周均有正文、题目与复测；内容发布齐全不代表学习者已完成，也不代表真实听力、独立写作或完整试卷能力已通过。8 个学科键包含三门候选第三科，用户同时学习其中 6 科。界面区分“完整讲解”“仅有周纲”“待补充”，不将未补齐的题目伪装为已经提供。

| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 常态 | 4 | 3 | 3 | 2.5 | 2 | 1.5 | 16 |

单位为小时，均为可选建议，不能决定学习序号。复习、测验与订正已包含在总量内。忙碌方案仅作应急；难以完成时按实际情况调整，不要求提前跳周。

## 开发与验证

使用 Node.js 24 和 npm。

```sh
npm ci
npm run dev
npm run typecheck
npm test
npm run build
npm run test:e2e
```

本地浏览器测试默认使用已安装的 Chrome。需要使用 Playwright Chromium 时：

```sh
npx playwright install chromium
```

将 `PLAYWRIGHT_CHANNEL` 环境变量设置为 `chromium` 后运行 `npm run test:e2e`；也可用 `PLAYWRIGHT_EXECUTABLE=/path/to/chromium` 指定已安装浏览器。测试覆盖桌面及手机布局、双主题对比度、刷新保存、周隔离、重复操作、无效备份、覆盖确认与科目切换。截图在 `test-results/`，报告在 `playwright-report/`；这些本地验证文件不会提交到仓库。

测试默认在独立端口 `5188` 启动自己的服务器，端口已占用时直接报错，不复用其他应用。受限 Windows 环境若无法自动清理测试服务器，可先在单独终端运行 `npm run dev -- --port 5188 --strictPort`，仅在确认这是本项目后，将 `PLAYWRIGHT_EXTERNAL_SERVER` 设置为 `true` 再测试，最后停止自己启动的服务器。CI 默认自动管理服务器。

## GitHub Pages

采用 **GitHub Actions 部署**，不是分支部署。仓库根目录包含 `.github/workflows/pages.yml`。

1. 在现有仓库的 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
2. 推送到 `main`，或在 Actions 中手动运行 **Deploy to GitHub Pages**。
3. 工作流安装依赖、运行单元测试、类型检查与构建、桌面/手机浏览器测试，再上传 `dist/` 并部署。

默认生产 base 为 `/study-plan-2028/`，对应项目 Pages 路径。开发环境 base 为 `/`。其他仓库名可通过 `VITE_BASE_PATH` 覆盖。站内使用 hash 导航，专注课可直接链接为 `#learn/3/math/prepare`；刷新保留阅读位置，浏览器前进/后退可返回已浏览的小节，无需服务端重写。

构建输出可直接用于 Pages：`dist/index.html`、`dist/assets/` 与图标。使用 `npm run preview` 后访问终端地址下的 `/study-plan-2028/`。目标网址为 `https://pbsmart.github.io/study-plan-2028/`，是否已上线须以 GitHub 部署结果为准。

## 本地数据与备份

- 内置课程没有账号、本站后端或分析埋点，无需 API 密钥。可选 AI 问答需要用户自己的 DeepSeek API Key，只有主动发送才连接 DeepSeek 官方 API。
- 所有用户记录保存在当前浏览器、当前来源的 `localStorage`，键为 `xunxu.gaokao.v1`。
- 任务勾选不增加时长；计时不自动保存，只有确认实际学习后才写入。切到后台自动暂停，刷新会丢弃未保存计时。
- 日志日期只记录实际发生时间，不决定学习周。一个学习周的日志可以跨多个日历周；日期不能晚于今天，所有新旧记录同一天累计最多 24 小时。
- JSON 备份 v2 包含 `version`、`currentWeek`、`firstCompleted`、`settings`、`weeks`、`legacy`，限制 5 MB。校验字段、枚举、学习序号、任务归属、日志日期、全局唯一记录 ID、整数时长及每日总量；确认覆盖前不会更改现有记录。
- v1 备份仍可导入。首次加载旧版记录时，先在 `xunxu.gaokao.v1.pre-v2` 保存原始快照，再写入 v2。旧日历日志保留在 `legacy.weeks`，旧预计日期仅留在备份元数据中，不用于安排课程；旧首四周打卡保持独立。旧日志不会被猜测分配到某个新学习周。写入失败时保留可访问的原记录并提醒导出。
- 更换浏览器、设备、域名或清理站点存储会影响记录；请定期导出。备份可能包含自己的学习信息，请自行保管，不要提交公开仓库。
- 官方资料链接仅在点击后打开外部网站；页面本身不加载第三方字体或统计脚本。

### 可选 DeepSeek 问答

在专注阅读页点击「问 AI」。Key 输入为密码框；不保存时只在这次打开期间使用，勾选风险同意并点击「保存 Key」后才写入独立的 `xunxu.deepseek.api-key.v1` localStorage。可随时「清除 Key」。本地存储不是加密保险箱，同源脚本（GitHub Pages 同域名下的其他项目也同源）、浏览器扩展或能使用设备的人可能读取，请只在可信个人设备保存。不要把真实 Key 发到聊天、提交仓库、写进问题或运行截图测试。

- 固定直连 `https://api.deepseek.com/chat/completions`，当前模型为官方文档列出的 `deepseek-flash`，非思考模式、非流式、最多 2048 输出 token。不支持自定义地址或第三方代理，不创建服务器或付费服务。
- 同一周同一科支持连续追问。只有点击「发送给 DeepSeek」才发送辅导提示、当前问题、明确选中的一份新资料，以及预览中列出的本课历史问答。新资料默认不选；基础课只附一个知识块或一道题，深化课只附当前小节或一道题，不自动附课程答案、评分、进度、日志、整课，图片不发送。历史问题当时附带的资料仍属于该轮内容，在完整发送预览中可查看。
- 历史按最近完整成功问答对裁剪：最多 6 轮，整次输入最多 32,000 字符、估算 20,000 token。保留固定辅导提示和当前问题/资料，舍弃更旧整轮，不跳过最新大轮去拼接更老的零碎内容。不调用 AI 摘要，不产生额外摘要费用。估算使用每条消息 UTF-8 字节数除以 3 向上取整，再加 8 的开销，只是本地预算启发值，不是 tokenizer 或账单。
- 发送前显示历史轮数、消息条数、具体轮号、未附带旧轮数和输入估算，支持展开逐条核对所有发送文本，也可取消「附带本课最近的完整问答」进行单次问答。仅成功回答进入历史；失败、取消或过期返回不进入历史，没有自动重试。
- Key 只进入官方请求的认证头，不在 URL、应用日志、错误消息、学习备份或对话内容中。浏览器禁止跟随重定向，不发送 Cookie 或 Referer。学习备份导入导出不读写 Key。
- 问答仓库只存当前页面内存，按 week + subject 隔离，不使用 localStorage/sessionStorage/IndexedDB 或备份。关闭重开和同课切小节后仍保留；切课隔离，回来可恢复该课当前内存对话，刷新/关闭页面清空。每课最多保留最近 40 轮、120,000 字符，超出时移除最早整轮并显示提示。可「清空当前会话」。
- 关闭/取消/切小节/切课/清空会中止在途本地请求，60 秒超时；身份、控制器和会话版本共同阻止迟到回答污染当前会话。已经发送到服务商的请求仍可能处理和计费。
- 回答以纯文本显示，不执行 HTML、链接、脚本或模型指令，不自动评分、改打卡或跳周。AI 可能出错，应核对课内解析。
- 401/403、402、429、模型/请求错误、服务错误、网络/CORS、超时与取消有独立提示；不显示服务商原始错误体。无 Key 的官方 OPTIONS 预检在 2026-10-14 对 `https://pbsmart.github.io` 返回允许 POST 与 authorization/content-type。未使用真实 Key 或计费 POST 验证；实际可用性、账户余额、计费和浏览器环境仍以用户首次主动请求为准。

官方依据：[首次调用](https://api-docs.deepseek.com/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion/)、[思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)、[模型与计费](https://api-docs.deepseek.com/quick_start/pricing/)。模型与 API 规则可能变化，维护时应重新核验。

AI 检查：`npm test`、`npm run build`、`npm run check:bundle`、`node scripts/check-ai-bundle.mjs`；`tests/e2e/deepseek.spec.ts` 与 `tests/e2e/conversation.spec.ts` 对桌面/手机使用纯 mock 网络，绝不要求真实 Key 或计费请求。

## 使用边界与内容维护

本计划是通用学习建议，不保证成绩或录取，不把历史分数作为未来保证线。内置讲解与基础题是原创教学材料，没有智能评分、录取预测或等级赋分功能。报考、选科、教材范围、体检及考试安排以当地当年官方发布为准。

历史参考：[郑州市教育局河南 2026 年报名问答](https://zzjy.zhengzhou.gov.cn/ptgzyjs/9673247.jhtml)、[阳光高考听力及计分历史资料](https://gaokao.chsi.com.cn/gkxx/zc/ss/202402/20240229/2293259554.html)。历史规则不能替代 2028 年通知。

课程接口见 [CONTENT_SCHEMA.md](CONTENT_SCHEMA.md)，主数据在 `src/curriculum/study-plan-content-v1.json`，适配器和内容类型位于同目录。官方评析来源索引独立保存于 `past-paper-sources.json`。数据模型、迁移与校验在 `src/model.ts`；旧版校验保留于 `legacy-model.ts`；课程呈现在 `src/components/WeekLesson.vue`。修改结构须同步迁移、校验与测试。公开代码不得加入姓名、个人成绩、聊天记录、令牌或用户备份。

## 扩展教学内容

诊断测评展示完整题干、答案解析、逐点评分、总分、结果解释和补弱映射；所有评分均由学习者自行核对，不提供智能评分或高考分数预测。英语写作保留前文、给定段首句、完整参考段及各题自己的词数口径；已嵌在题干或答案中的相同内容不重复展示。

听力相关课次目前仅有文字脚本预训练，未附音频。阅读脚本、文字复测及打卡不能认定真实听辨已经达标。课程中的古诗文原典明确保留作者篇名、出处与材料说明；原创设问不意味着原典由本站创作。

课程主JSON仍是84周基础内容的唯一原始文件。Vite构建插件在构建时适配为轻量导航/覆盖摘要和84个独立动态课程块；首页、路线和学习周计划只读摘要，进入专注页才加载当前周。加载器缓存成功结果、去重并发请求，失败允许重试；切周或退出后不显示旧请求结果。课程数据没有删减，按需加载优化的是初次下载量，累计阅读全部84周仍会下载全部内容。

构建后运行 `node scripts/check-curriculum-bundle.mjs`，会检查真实入口静态依赖图、84个独立动态周块与首屏大小预算，不仅比较入口文件名。生产默认base仍为 `/study-plan-2028/`。

第1—8周语文、数学、英语、物理、化学提供独立深化试点，保存在 `src/curriculum/enriched-week-01/` 至 `enriched-week-08/`，按各自学习周动态加载。深化周号、版本、图解与累计诊断映射由 `src/curriculum/enrichment-config.ts` 明确配置。保留原84周基础JSON；第9—84周及三门候选第三科没有被标成深化版。每周五核心科870分钟，第三科预留90分钟且仍待确认；复习、测验与订正包含在预算内，忙碌配额可跨周期完成同一学习周。

前测、逐小节自检、阶梯例题、独立练习、20分测评与订正均有单独展示；答案与评分默认收起。第4周的20分测评是第1—4周累计诊断，替代常规短测，未新增试卷或时长。五科累计技能映射仅在订正页的默认折叠区展示，关联本周补救小节；同一技能可涉及多个周次但分值只计一次，不据此自动评分或达标。第8周同样以一份20分累计诊断替代常规短测，主查第5—8周，必要第1—4周只作前置回查，不代表全面覆盖八周知识。回查标题从实际技能周次计算，正文明确只涉及本次诊断的技能。不同作者映射格式经构建期验证后统一展示，冻结JSON未修改。

第1周物理图沿用本地结构化SVG；第2—8周分别使用4、6、7、10、10、10、10张原创静态SVG，配等效文字、浅色画布及手机内嵌横向查看，无第三方图片请求。第3周数学区间图含例题答案，配置为仅在例4解析折叠区出现，不在关联讲解中提前显示；第3周物理短测2的题设图也位于该题答案折叠区，题干已有完整等效文字。第4周七图和第6周十图均为对应小节的教学示意。第5周物理例4的面积图仅在答案折叠区显示，其余九图为教学示意。第5—7周仍为普通20分短测，无新增累计诊断或映射。第7周物理图4同样只在例4解析折叠内，其余九图为教学用；第8周十图全部为关联章节的教学图。静态图保留原端点、单位与粒子关系，不套用数轴组件重画。

测试中的 `tests/fixtures/weeks-three-four-integrity.json` 保存作者冻结哈希、字节数与源路径；第4周三份根目录映射仅移动到课程 `assets/` 中，字节未变。构建检查继续限定首屏JS小于350KB（gzip110KB）、每周小于450KB（gzip150KB）；57张静态SVG各小于50KB、每周图合计小于75KB、全图合计小于325KB，并验证只有所属周动态块引用、嵌套base路径正确。全图总门槛仅随新增两周图数量调整，单图、单周与JS门槛未放宽。第5—6周导出的SVG经过内容作者安全重导出，移除外部DTD与冗余字形路径，原课程JSON不变；冻结哈希另见 `tests/fixtures/weeks-five-six-integrity.json`。第7—8周41个原稿、图解与累计映射的字节/哈希记录在 `tests/fixtures/weeks-seven-eight-integrity.json`。包体报告单独列出按需AI代码，并在全站JS合计中纳入这些可选块，不将其误算为首屏下载。

已有v2通用打卡保持原样，深化页明确提示历史打卡不代表新版课程已完成，需按新标准重新核对。没有自动评分、自动掌握或自动跳周。
